## Этап 2 — корректность исследований (выполнено в текущем рабочем дереве)

- UC sale использует `Systems`/`Discovered` из журнала: при частичной продаже удаляются только перечисленные системы/тела; событие без состава сохраняет прежнюю семантику полной продажи.
- `SellOrganicData.BioData` сопоставляется по codex `Variant`/`Species`/`Genus`. Несопоставимые legacy-идентификаторы не обнуляют оставшуюся оценку; пустой список сохраняет семантику полной продажи.
- Неполный `Scan` не получает бонус первооткрытия автоматически. В live state и catalog есть `DiscoveryStatusKnown`/`MappingStatusKnown`; очередь не повышает приоритет на основании неизвестного флага.
- Повторный Scan после DSS не уменьшает текущую оценку. Ledger сбрасывается при смене Commander, поэтому replay нескольких профилей не смешивает деньги.
- Bootstrap открытого journal теперь проходит через history accumulator, а смена каталога сбрасывает его контекст. Схема SQLite поднята до версии 3: старые бонусные признаки и маркеры импорта безопасно переиндексируются из журналов.

Полный набор тестов после этого этапа: **728 пройдено**, Release-сборка solution без ошибок. Реальные журнальные fixtures с несколькими страницами продажи и live restart всё ещё желательно добавить перед merge gate.

## Этап 4 — Mining v2 Personal Intelligence (выполнено в текущем рабочем дереве)

- Личная статистика точного кольца больше не переключает оценку качества скачком после минимального порога: она постепенно смешивается с внешним замером по confidence выборки.
- Для кольца рассчитываются среднее и медианное содержание цели, hit-rate, число проб/результативных астероидов, средняя и лучшая скорость добычи; confidence и валидная скорость участвуют в итоговом порядке результатов.
- В карточке места отображаются median/confidence, а пояснение источника теперь соответствует blended ranking. Новые провайдеры не добавлялись.

После этапа 4: **729 тестов**, Release-сборка solution без ошибок. Нужна ручная проверка на двух кольцах с малой и большой личной выборкой.
